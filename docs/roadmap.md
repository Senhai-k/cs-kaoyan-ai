# 项目路线图

## 1. 当前目标

项目不再扩充零散功能，后续只围绕三个结果推进：

- 数据可用：重点院校关键字段有年份、来源、核验状态和更新时间。
- 决策可信：条件匹配、数据可信度和报考风险分开表达。
- 系统可运营：资料可导入、审核、发布、回滚、评估和监控。

## 3. 已交付主线

### 产品与前端

- 用户端形成画像、检索、推荐、候选、对比、详情、问答和导出闭环。
- 招生计划与复试线按同一指标至少两个年度计算趋势；数据不足时明确拒绝推断。
- 候选分组和 300 字个人备注在本机自动保存，兼容旧版存储并纳入导出。
- 管理端按数据覆盖、基础档案、知识资料、招生指标和 Agent 运维分区。
- 状态可恢复，桌面 1440px、平板 900px、移动 390px 有 Playwright 回归。

### 数据治理

- 删除无法核验的演示招生数字，空缺字段明确显示待核验。
- 建立来源、原文、切片和结构化字段的追溯关系。
- 将数据缺口转换为带优先级、负责人、截止日期和 URL 待办的任务。
- URL 待办可从已登记研招入口受控发现同站候选；人工采用只更新待办，不自动采集、发布或索引。
- 408 目录批次保存原始证据和 SHA-256；2026 计算机核心范围批次为 `complete=true`。
- 只将唯一的“专业：N（不含推免）”写为统考计划；方向级、院系级、学科级和冲突人数拒绝结构化。
- 只将带明确标签的目录复试原文写为初步复试信息，不推断时间、差额比例和成绩权重，也不替代学院复试细则。
- 国家线独立保存学科门类、A/B 类总分和单科线；自主划线院校只展示政策参考，不写入院校复试线。
- 学校基本线使用独立表和导入批次，保留文章及图片 SHA-256；武汉大学计算机相关行未公布时保持空值，不用国家线或其他学院分数代替。
- 院校详情返回全部 408 专业和科目组合；同专业多组合的研究方向与备注在幂等导入时累积去重。
- Flyway V10 将 10 所重点院校的已核验官方证据移入生产 MySQL，避免真实资料只存在开发 H2。
- 拟录取名单通过本机加盐匿名化、专业映射预览和草稿发布，不存姓名或考号，不覆盖人工计划，不将专项计划混入普通计划。

### Agent 与 RAG

- 从简单问答升级为可规划、可并行、可中断恢复的 LangGraph 工作流。
- 增加混合召回、上下文扩展、特征重排、范围过滤和引用检查。
- 建立 RAG、规划、证据策略和知识审计困难集及统一质量门禁。
- 质量门禁升级到 `quality-gate-v3`，引用必须落到来源 URL；真实规划 A/B 还必须满足质量、Usage、费用、失败数和越界提议阈值。
- 长任务持久化，支持受限并发、超时、取消、重试、trace、离线回放和运营诊断。

### 生产工程

- MySQL 使用 Flyway V1-V15，H2 保留开发和自动化测试用途。
- 管理账号、角色、BCrypt 密码和 SHA-256 会话 token 持久化。
- 资料支持版本快照、发布批次和并发修改保护。
- 已登记精确官网文章支持默认关闭的定时监测，数据库租约避免多实例重复抓取，失败按上限退避重试。
- 建立 H2 备份恢复、损坏清单拒绝、服务降级和会话恢复演练。
- 增加 Actuator、Agent 指标、Prometheus 告警和八服务 Compose。

## 4. 下一阶段顺序

### P0：运行证明收口

1. 已验证官网变化汇总 API、Micrometer 三项指标和 24 小时积压告警的真实运行名称与零积压输出。
2. 2026-07-27 已完成 Flyway V1-V15、1830 条目录与 34 条学校基本线幂等导入、1876 份资料与 1900 切片索引、拟录取匿名预览、HTTP 探测和 RAG 实查。
3. Alertmanager webhook 已支持环境配置，本机 firing/resolved 实际投递通过；上线时替换为组织实际 URL 并复跑演练。
4. 安装 Tesseract `chi_sim` 后用真实扫描件记录准确率、耗时和失败样本。

### P1：模型与 RAG 证据

1. 2026-07-23 已完成真实模型 A/B：10/10 Exact Match、目标召回 1.0、平均 5816ms/案例、输入/输出 3316/1424 Token、失败和越界提议均为 0。
2. 供应商未公开 Token 单价，实验显式使用 `UNMETERED`，不生成虚假金额；实时运行和防篡改回放均通过 `quality-gate-v3`。
3. 跨校、年份冲突和长表格困难案例已纳入 30 案例集；继续补来源失效和页面改版案例。
4. 已完成 CrossEncoder 对照：特征重排目标 Recall@1/MRR@5 为 0.9333/0.9808、约 91ms/案例；CrossEncoder 为 0.8/0.9231、约 2626ms/案例，因此保留特征重排。

### P2：真实数据补全

1. 2026-07-23 已使用本人合法会话完成当前目录分页采集；Cookie 未落盘，未绕过登录、验证码或限流。
2. 2026 国家线和自主划线适用关系已完成；国家线、学校基本线、学院线和专业线在模型与页面中分离。
3. 全国计算机核心专业目录、考试科目和用户侧专业组合展示已完成；拟录取匿名导入框架已完成，下一步登记精确学院公告 URL 并导入首批真实名单。
4. 继续区分目录计划、统考计划、推免计划、复试阶段名额、普通计划与专项计划；真实名单必须先预览映射并进入草稿，管理员确认后发布。

### P3：使用体验

1. 用真实用户任务做可用性测试，记录完成时间、回退次数和误解点。
2. 优先优化候选收窄、证据核验和对比决策，不增加无数据支撑的图表。
3. 为数据缺失、服务降级、任务失败和权限不足提供明确下一步操作。

## 5. 每轮完成标准

每轮交付必须同时具备：

1. 代码和必要迁移。
2. 自动化测试与真实接口冒烟。
3. 数据来源与质量检查。
4. 桌面、平板和移动端验证。
5. 文档只更新当前结论，不追加重复流水账。
6. 明确外部依赖、未验证项和下一轮输入。

数据数量增长不等于 Agent 能力增长，页面存在也不等于流程可用。
